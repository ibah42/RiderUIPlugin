# Sample sources

Whole real files the scanner is run over by `SampleFilesTest`, as opposed to the hand-written
snippets in `BraceScannerTest`. They are here because snippets only ever check what somebody
thought to write down: the bug that prompted this folder was a class quietly disappearing from a
generated file, in a shape nobody had written a snippet for.

## Adding one

Drop the file in. Every invariant in `SampleFilesTest` picks it up from the next run with no code
change -- balanced braces, in-bounds names, ascending offsets, a deterministic result.

The golden test needs one more step: a file beside it called `<name>.expected.txt`, holding one
line per block. Generate it once, **read it**, and commit it only if every line is what the
plugin should be saying about that source. A golden nobody read is a rubber stamp.

The same goes for a golden that starts failing. Regenerating it is a change to the plugin's
behaviour, so it belongs in `CHANGELOG.md` like any other. A diff the changelog entry does not
explain is the bug the golden was put here to catch.

Pick files that are hard rather than typical: generated code, deep nesting, wrapped signatures,
long base-type lists, string literals with braces in them.

## What is here

### `Zoo.EveryShape.cs`

The only hand-written one, and the only one that is not real code. Everything else here is
vendored, which is its value and also its limit: real code contains what its authors happened to
write, and three of the four UniTask files are pure Allman, so between them they exercised
almost no phantom line at all.

This one is deliberately exhaustive and deliberately mixed. Every type keyword including all
four record spellings, base-type lists in five shapes, types nested three deep with local
functions nested inside them, every member kind (static constructor, destructor, auto-property,
indexer with a default in its brackets, ten operators), tuple return types, default parameter
values holding braces and parentheses, lambdas named from a call and from an assignment, every
control construct and initializer that must be ignored, string literals of all five C# kinds
with braces inside them, `#if`/`#else` and `#region` -- and then a whole second namespace
written K&R so the move mechanic has something to draw.

It found the bug it was written to find: a constructor whose brace hangs off its `: base()`
line was not recognised at all. The one line in its golden with no name is explained by a
comment at that spot in the source.

### `Zoo.LongForm.cs`

The other hand-written one, and the answer to what `Zoo.EveryShape.cs` cannot test. That file is
wide and short: one of everything, almost every block three lines long. So it proves the
classifier and proves nothing at all about the rules that ask *is this block long enough to say
something about* -- the per-kind label lengths, the `[N]` repeated after a closing brace, the
block-span marker. None of them fire in it.

This one is sized on purpose. 4277 lines, 166 blocks, and of those: 46% are long enough to be
named at their closing brace, 16% long enough to report a span, 49 repeat their `[N]`. By line
rather than by block it is 60% named and 30% spanned -- the two figures differ because a block
that crosses a length threshold is by definition one of the longer ones and therefore holds more
of the file. Both numbers are worth keeping near half: a fixture where everything is marked
tests the rule no better than one where nothing is.

The valuable part is the probes that sit *on* the boundaries, one line either side, which is
where an off-by-one hides: functions at 29, 30 and 31 lines against a label threshold of 30;
functions at 59 and 60 against a span of 60; types at 49 and 50 against a label of 50; types at
99 and 100 against a span of 100; nested siblings at 14 and 15 against the 15-line `[N]` repeat.
Each is named after the boundary it straddles, and the golden is what keeps those names honest
-- the first draft of this file had `TypeJustUnderTheLabel` spanning 50 lines, which is over it,
and reading the golden is how that was caught.

Generated by `tools/gen_longform.py` rather than typed, so the sizes are exact. The generator
writes a manifest of what it meant to produce and that is cross-checked against what the scanner
actually measures; they agree on all 163 blocks it declares. Regenerate it by running the script
from the project root, then regenerate the golden and read the diff.

### The UniTask files

All four are from [UniTask](https://github.com/Cysharp/UniTask) by Cysharp, MIT licence,
vendored unchanged.

### `UniTask.WhenAny.Generated.cs`

Earns its place several times over: fifteen types in one file, each a nested `WhenAnyPromise`
class of a hundred to six hundred lines, every one of them declared with a base-type list
containing a tuple (`IUniTaskSource<(int, T1 result1, T2 result2)>`), and methods whose return
type is a tuple too (`public (int, T1 result1) GetResult(short token)`). That last shape is what
broke the classifier in 1.10.0 -- the name was taken to be the identifier before the first `(`,
and the first `(` there belongs to the tuple, not to the parameter list -- and the fifteen types
are what the span marker's "only in a file that holds more than one" restriction was built for.

### `UniTask.cs`

The hand-written counterpart to the generated file above, and the one with the awkward labels:
three conversion operators, two of them to a fully qualified type
(`public static implicit operator System.Threading.Tasks.ValueTask<T>(in UniTask<T> self)`), so
the golden shows exactly how long an `op` label can get. Also two structs of the same name at
namespace level (`UniTask` and `UniTask<T>`), each with its own nested sources and `Awaiter`, so
the sibling numbering has something real to number.

### `UniTask.Factory.cs`

Destructors that are not test fixtures (`~ExceptionResultSource()`), a static constructor, and a
lambda assigned through a constructor call -- `new Func<UniTask>(() =>` -- which is the case
where a lambda's label is borrowed from the call it is passed to rather than from an assignment
target.

### `UniTask.Delay.cs`

The densest of the four: eleven types, seven static constructors (one per promise pool), an
`enum`, and `readonly struct Awaiter : ICriticalNotifyCompletion` nested inside a
`readonly struct`. Nothing here was broken when it was added -- it is here to stay unbroken.
