# Allman View

Плагин для Rider (и любой другой IntelliJ-IDE), который **визуально** показывает код в стиле Allman,
не меняя ни одного байта в файле.

```
// в файле лежит                 // в редакторе видно
if (x) {                         if (x)
    Foo();                       {
} else {                             Foo();
    Bar();                       }
}                                else
                                 {
                                     Bar();
                                 }
```

## Как это сделано

Два примитива платформы, оба чисто визуальные:

1. **Fold region с пустым плейсхолдером** — `FoldingModelEx.createFoldRegion(start, end, "", null, neverExpands = true)`.
   Прячет исходную ` {` (и `else`/`catch`/`finally` при полном Allman).
2. **Block inlay** — `InlayModel.addBlockElement(lineEnd, relatesToPrecedingText = true, showAbove = false, ...)`.
   Рисует фантомную строку под строкой-владельцем на её отступе.

Ни то, ни другое не трогает документ. Копирование, поиск, компилятор, git и ReSharper видят
реальный K&R-текст — диффы остаются чистыми.

## Структура

| Файл | Что делает |
|---|---|
| `scan/BraceScanner.kt` | Лексер + поиск мест переноса. **Ноль зависимостей от IntelliJ**, покрыт тестами. |
| `AllmanController.kt` | Один на редактор: пересобирает фолды и инлеи по таймеру. |
| `AllmanService.kt` | Подписка на создание редакторов, `refreshAll()`. |
| `PhantomLineRenderer.kt` | Отрисовка фантомных строк. |
| `AllmanSettings.kt` / `AllmanConfigurable.kt` | Настройки + панель в Settings → Editor → Allman View. |

## Сборка

Нужен JDK 21.

```bash
# один раз, чтобы появился gradlew (нужна сеть):
gradle wrapper --gradle-version 8.14.3

./gradlew test        # тесты сканера
./gradlew runIde      # поднимает песочный Rider с плагином
./gradlew buildPlugin # build/distributions/allman-view-0.1.0.zip
```

Из IDEA/Rider: открыть папку как Gradle-проект. Если `gradlew` ещё нет — в диалоге импорта
выбрать «Use Gradle from: `gradle-wrapper.properties` file», IDE скачает дистрибутив сама.

Целевая IDE задаётся в `gradle.properties`:

```properties
platformType=RD          # RD = Rider, IC = IntelliJ IDEA Community (качается в разы меньше)
platformVersion=2026.2.2
```

Все используемые API платформенные, так что собирать и проверять можно против `IC`,
а ставить готовый zip в Rider.

## Что проверить в первую очередь

**Конфликт фолдингов — главный риск.** ReSharper ставит свои fold-регионы на тела методов и классов,
и они часто начинаются ровно с той `{`, которую мы прячем. `createFoldRegion` возвращает `null`
при пересечении — тогда строка просто остаётся в K&R (двойной скобки не будет, но и переноса тоже).
Если окажется, что не срабатывает на большинстве блоков — запасной план описан ниже.

**Запасной план:** вместо фолдинга красить `{` в цвет фона через `RangeHighlighter` +
`CustomHighlighterRenderer`. Скобка становится невидимой, но на её месте остаётся пустое место
шириной в символ. Уродливее, зато не пересекается ни с чем.

## Известные ограничения

- Строка под кареткой не переносится (настройка «Не трогать строку под кареткой»).
  Так каретку не выталкивает из схлопнутого региона прямо во время набора.
- Фантомная строка не получает номер в гуттере и не участвует в indent guides —
  вертикальные линии отступов будут разрываться.
- В фантомную строку нельзя поставить каретку: это не текст.
- Сканер полностью пересчитывает документ по таймеру (200 мс после правки).
  На файлах в десятки тысяч строк это стоит померить и, если надо, сделать инкрементальным
  (кэш состояния лексера на начало каждой строки).
- `} while (x);` у `do`-цикла намеренно не разносится.
